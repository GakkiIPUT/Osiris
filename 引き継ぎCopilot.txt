引き継ぎドキュメント（最小で全体が把握できる版）
1.	全体設計と目的
•	目的: 次の担当者が「読める・理解できる・安全に変更できる」状態で開発を継続できるようにする。
•	方針: 巨大だった BoardManager を partial 分割し、純粋ロジックはエンジンへ委譲（RotationEngine, GridModel）。MonoBehaviour 側は「生成・見た目・オーケストレーション」のみに集中。
2.	フォルダ/主なスクリプトの責務
•	Gameplay/BoardManager.cs
•	設定（Prefab/マテリアル/スピード等）と公開APIの入口。MonoBehaviour 本体。
•	Gameplay/BoardManager.Build.cs
•	Build/破棄/初期化/Exit 開閉/壁見た目/外周Floor再計算。Awake/OnEnable/OnDisable/OnDestroy 含む。
•	Gameplay/BoardManager.Items.cs
•	アイテム辞書 itemAt、拾得 TryPickupItemAt、泥棒(d/e)→宝箱/鍵への変換。
•	Gameplay/BoardManager.Vision.cs
•	LoS（角抜け防止）、視界のON/OFF/更新、BlocksVision。
•	Gameplay/BoardManager.FreePreview.cs
•	自由回転プレビュー（Pivot/Group 親子付け、回転、復帰、プレビュー中の壁マテリアル推定）。
•	Gameplay/BoardManager.EditorPreview.cs
•	OnDrawGizmos のみ（床/壁/出口/役者/アイテムプレビュー）。
•	Gameplay/BoardManager.Rotation.Helpers.cs
•	RotatePreview, StepValidity, IsCenterWithinLimit, AreaContainsLocked, AreaCrossesOuterRing, GetStepValidity。
•	Gameplay/BoardManager.Rotation.Core.cs
•	回転の実行入口（TryRotateArea, RotateAreaInstantIfPossible）
•	安全判定（WouldBeSafePartial/180）
•	衝突判定（WouldPlayerOverlapGuard/180）
•	回転後のタイル/アイテム/ガード/プレイヤー座標更新、見た目の再適用。
•	Gameplay/BoardManager.Utility.cs
•	Grid座標⇄ワールド座標、InBounds、レベルテキストの ParseRows/NormalizeRows。
•	Gameplay/BoardManager.ModelBridge.cs
•	Board の現状態を GridModel にスナップショット化（SnapshotGridModel）
•	RotationEngine を呼ぶ薄いラッパ EngineRot90/Rot180/AreaHasExit。
•	Gameplay/Rules/RotationEngine.cs
•	純粋ロジック（Rot90/Rot180、回転マップ生成 BuildCellRotationMap、AreaHasExit）。
•	Gameplay/Model/GridModel.cs
•	盤面の不変スナップショット（Width/Height/Core オフセット、Cells/WallOrigin/OuterRingFloor ほか）。
3.	実行フロー（重要箇所）
•	レベル生成（Build）
1.	ParseCellsFromLevel → Cells/WallOrigin/OuterRingFloor を作成（外周ON時は Core を展開）
2.	Hierarchy クリア → タイル/役者/アイテムの生成
3.	必須アイテム列挙（'i' と 'e' を鍵としてカウント）→ TurnManager.InitRequiredItems(requiredSymbols)
4.	Exit の開閉更新（TurnManager.onRequiredChanged → SetAllExitsOpen）
5.	視界可視化更新/壁見た目適用/選択オーバレイ初期化
•	回転（RotateAreaInstantIfPossible）
1.	安全判定（外周跨ぎ・Anchor/Exit含有・ガード衝突）→ NG なら中止
2.	RotationEngine.BuildCellRotationMap で dest→src マップを構築
3.	Cells/WallOrigin を転写、外周 Floor 再計算
4.	タイルGameObjectの位置更新（Y高さは維持）、アイテム/ガード/プレイヤー位置の更新
5.	壁見た目更新/視界更新
4.	設定と挙動のポイント
•	Outer Ring（autoGenerateOuterRings）
•	最外周 Anchor 帯（@）と内側の外周 Wall 帯（#）を自動生成。
•	論理的には外周の # は Floor として扱い（視界も通す）、回転で Core 外へは出られない（AreaCrossesOuterRing が禁止）。
•	アイテムと必須進捗
•	itemAt: 位置→(記号, GameObject)
•	'i'（鍵）取得で進捗、't'（宝箱）はスコア、'd'/'e' は侵入不可で視認後に 't'/'i' に変換。
•	TurnManager.OnItemPicked('i') / OnTreasurePicked() を通知。
•	Guard/LoS
•	HasLineOfSight は supercover Bresenham + 角抜け抑止。
•	BlocksVision は Wall/Anchor で遮蔽。
5.	命名/規約/整形
•	.editorconfig が規範。保存/クリーンアップで攪乱を抑止。
•	実行: Run Code Cleanup（Ctrl+K, Ctrl+E）, Format Document（Ctrl+K, Ctrl+D）
•	解析: Analyze > Run Code Analysis、複雑度確認: Analyze > Calculate Code Metrics
•	命名
•	型/メソッド/プロパティ=PascalCase、引数/ローカル=camelCase、private フィールド=_camelCase（段階移行中）。
•	アクセス
•	可能な範囲で public フィールド→[SerializeField] private + public get に段階移行（現状保持）。
6.	よくある変更手順（HowTo）
•	新しいガードを追加
•	BoardManager.guardTypes に記号/Prefab/色を追加
•	必要なら ConfigureGuardFromSymbol でパターン/向きを記号別に指定
•	Prefab に GuardController を付与
•	新しいアイテム記号を追加
•	BoardManager.itemTypes に記号/Prefab/色を追加
•	itemAt の運用方針に合わせ TryPickupItemAt/Transform… を拡張（必要なら TurnManager 側も）
•	新しいステージを追加
•	Assets/Level/Stage_txt に txt を追加 → 読み込ませて SetLevelFromText
•	行長が不揃いなら NormalizeRows が右パディング。Core外自動生成ON/OFFは BoardManager で制御。
•	回転ロジックをいじる（原則 Engine 側）
•	Rot90/Rot180/AreaHasExit/BuildCellRotationMap は RotationEngine を編集。
•	BoardManager は SnapshotGridModel 経由で呼ぶだけ（MonoBehaviour 側の生成/見た目更新に専念）。
7.	既知の注意点/制約
•	WouldPlayerOverlapGuard は「プレイヤーが回転に追従する設定（rotatePlayerWithArea）かつ範囲内なら新座標で判定、そうでなければ据え置き位置で判定」へ修正済み（範囲外の誤検出を避けるため）。
•	Editor の OnDrawGizmos は ParseCellsFromLevel を呼ぶ（プレビュー更新）。実行時の Build は行わない。
•	TurnManager は Find で拾うため、シーン上に1つである前提。複数/未配置のときは Build で生成。
8.	ビルド/起動手順（最小）
•	シーンを開き、BoardManager の Prefab/マテリアルが割り当て済みであることを確認。
•	Run Code Cleanup → ビルド。
•	再生。カメラ追従（CameraFollow）、Exit 開閉、回転（T/ドラッグ）をスモーク。
